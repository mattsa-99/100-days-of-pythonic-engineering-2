El problema

Se llama data skew.

En un join, Spark junta las filas con la misma key (la columna del join, ej. customer_id). Si una key tiene casi todas las filas, una sola partición recibe casi todo.

Partición
Un pedazo de tus datos. Cada una la procesa una tarea, en paralelo.
Shuffle
Mover filas por la red para juntar las de la misma key.

Arreglo 1 y 2

Lo barato, primero.

1Quita las filas con key NULL

Una key NULL nunca encuentra pareja en el join, pero todas esas filas igual viajan juntas a la misma partición.

events = events.filter( F.col("customer_id").isNotNull() )
2Deja que Spark lo parta solo

AQE (Adaptive Query Execution) mide las particiones mientras el job corre y divide las que quedaron gigantes.

spark.conf.set("spark.sql.adaptive.enabled", "true") spark.conf.set( "spark.sql.adaptive.skewJoin.enabled", "true")

Arreglo 4 · El código

Ahora, en código.

1Salt al azar en la tabla grande

rand() da un número entre 0 y 1. Por N y a entero: 0, 1, 2 o 3.

N = 4 # en cuántas partes dividir la key big = big.withColumn( "salt", (F.rand() * N).cast("int"))
2Una copia por salt en la pequeña

explode convierte la lista [0, 1, 2, 3] en 4 filas.

salts = F.array(*[F.lit(i) for i in range(N)]) small = small.withColumn("salt", F.explode(salts))
3Join por key + salt
joined = big.join(small, ["key", "salt"])

El costo: la tabla pequeña crece N veces.
