Fix 1 y 2: lo gratis primero

1

Filtra las llaves nulas antes del join

Los nulos nunca hacen match, pero sí terminan juntos en una sola partición.

2

Verifica que AQE esté activo

Adaptive Query Execution parte las particiones sesgadas en el join automáticamente.

spark.conf.get(
    "spark.sql.adaptive.skewJoin.enabled"

CÓMO ARREGLARLO · CONEXIÓN CON DÍA 35/7

Fix 3: si la otra tabla es pequeña, broadcast

Sin shuffle no hay partición sesgada: cada executor recibe una copia de la tabla pequeña y hace el join localmente.

broadcast_join.py
from pyspark.sql.functions import broadcast

joined = big.join(broadcast(small), "key")

✅ Úsalo cuando

La tabla pequeña cabe cómodamente en la memoria de cada executor.

⚠️ Evítalo cuando

Las dos tablas son grandes. Ahí toca el fix 4.

CÓMO ARREGLARLO · MÁS ESFUERZO6/7

Fix 4: salting, reparte la llave caliente en N pedazos

salted_join.py
N = 8  # ajusta según el tamaño de la llave

# Lado grande: sal aleatoria 0..N-1
big = big.withColumn(
    "salt", (F.rand() * N).cast("int")
)
# Lado pequeño: una copia por cada sal
small = small.withColumn(
    "salt",
    F.explode(F.array(
        *[F.lit(i) for i in range(N)]
    ))
)
joined = big.join(small, ["key", "salt"])
La llave caliente ahora se procesa en N tareas en paralelo. El costo: la tabla pequeña se multiplica por N.
